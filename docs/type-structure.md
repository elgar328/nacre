## 1. 확정된 것 (실측이 뒷받침함 — 다시 논쟁하지 말 것)

### 1.1 평면의 진실은 **세 점**이다 (구현 완료, `a6e8ac1`…`814db1a`)

계수는 **파생된 이름**이고 캐시다. 이유는 폭이다:

| | 비트 | `i128` 적합 |
|---|---|---|
| 벽 평면의 **계수** | median 159 · max 213 | **25.8%** |
| 그 계수를 만든 **링 좌표** | max 107 | **100%** |

★ 계수는 두 점차의 **곱**이라 점의 약 2배가 든다. 문서의 한 줄이 그것을 그대로 보여준다 —
프레임 안의 벽 평면은 세 점 `(x1,y1,0)`, `(x2,y2,0)`, `(x1,y1,d)` 로 **산술조차 없이** 정해지는데,
그 이름은 `(y2−y1)·X − (x2−x1)·Y + (x2·y1 − x1·y2) = 0` 이라 **곱이 있다.**

⇒ `push_surface_with_points(surface, def, points)` 가 유일한 문이고, 계수는 거기서 유도된다.
생산자는 계수를 못 준다 ⇒ **한 평면을 두 가지로 말할 수 없다.**

### 1.2 그 밖에 실측으로 굳은 사실들

| | |
|---|---|
| 이름을 못 만든 평면 | **472 / 122,406 (0.39%)** — `UNNAMED_PLANES` |
| 점 → 법선(넓은 중간값) | **45,434 / 45,434 (100%)** — 법선은 항상 `i128` 에 든다 |
| 그 법선 == 이름의 법선 | **45,030 / 45,030** (부호 정준화 후) |
| ★ 프레임을 막는 것 | 이름이 아니라 **`n·n`** (실측 133비트, 한계 127) |
| 프로덕션 f64 폴백 | 스위트 전체에서 **1~2건** (`decline=no-exact-frame`) |
| 점 없이 미는 `push_surface` | **4곳 전부 `#[cfg(test)]`** — 프로덕션은 전부 `with_points` 를 지난다 |
| ★ 불리언은 surface 를 **안 만든다** | `a_boolean_mints_no_surface` (`nacre-ops/src/tolerant.rs:1314`) |
| `Vertex.definition` | `3a` 가 **더했을 뿐**, 100% 커버. **아직 아무도 안 읽는다** |
| ★ 발견된 정점의 정확 좌표 | Cramer 분자 = 3×3 계수 행렬식 ≈ **160–480비트** ⇒ **`Rat` 에 안 들어간다** |

### 1.3 방향이 정해진 것

- ★★★★★ **모션은 «면» 이 든다.** 정점 = 세 면의 교점이므로 면이 모션을 들면 교점은 정의상
  따라온다. 정점에 또 달면 **3중 중복**이다. (`truth-and-cache.md` 「점」)
- ★★★★★ **`Rat` 자체를 넓히는 것은 기각.** (`design.md:68` · `overview.md` 「비트 폭발」 ·
  dev-log 5510) 넓힐 수 있는 것은 **중간값**뿐이다.
- ★★★★ **datum 평면(모서리 세 개로 평면)은 M5 범위다** — 곡면이 없으므로 지금 구현할 것.
  (사용자 확정, 2026-08-05)
- ★★★ **`SurfaceDef` 의 셋 중 둘은 `Option<Handle<MotionNode>>` 다.** `Constructed`=None,
  `Moved{m}`=Some(m). 셋째 `Inexact` 는 *"진실이 없다"* — **다른 질문**이다.

## 2. 미결 — **이 문서가 답해야 할 것**

### Q1. `Surface::Plane` 의 세 점은 무엇인가

```rust
// (A) 오늘
surface_points: HashMap<Handle<Surface>, [[Rat; 3]; 3]>

// (B) 핸들
Plane { points: [Handle<Vertex>; 3], motion: Option<Handle<MotionNode>> }
```

★ **(B)를 밀어붙이는 것**: datum 평면의 세 정점 좌표는 `Rat` 에 안 들어간다(1.2 마지막 줄).
저장할 수 없으므로 **가리켜야** 한다.
★ **(A)를 지키는 것**: 오늘 동작하고, 좁고, 종료가 자명하다.

### Q2. `VertexDef` 에 좌표 변종이 필요한가

```rust
pub enum VertexDef {
    ThreePlane([Handle<Surface>; 3]),
    At([Rat; 3]),     // ★ 필요한가?
}
```

★ 오늘 `definition: None` 인 자리가 **둘** 있고, 둘 다 «교점이 아닌 점»이다:

| | 자리 | |
|---|---|---|
| ① | **스케치 프레임의 base 정점** (`nacre-ops/src/ops.rs:1048`) | 프레임 안의 좌표 `(u,v,w)` 그 자체. `Origin::Moved{base, motion}` 이 가리키고 `shared_base` 가 스케치를 통째로 소거하는 근거. ★ 그런데 그 «진실» 이 **f64 `point`** 다 |
| ② | **프로파일의 공선 정점** (`nacre-ops/src/ops.rs:1021`) | 두 벽이 한 평면(interning ⇒ 한 핸들)이면 셋이 점이 아니라 **직선**을 지목 |

★★ Q1 이 (B)면 `At` 은 **필수**다 — 구성 평면의 세 점이 정점이어야 하고, 그 정점은 교점이 아니다.
Q1 이 (A)면 `At` 은 ①②를 위해서만 필요하다.

### Q3. `Vertex` 의 최종 형태 — `point`·`origin` 은 어떻게 되나

```rust
// 오늘
pub struct Vertex { point: Point3, origin: Origin, definition: Option<VertexDef> }

// truth-and-cache.md 의 목적지
pub struct Vertex { surfaces: [Handle<Surface>; 3] }     // ★ 그것뿐
pub struct PointCache { coord: Point3, tol: [f64; 3] }
```

★ 목적지는 `Origin` 을 없앤다: `Discovered{tol}` 의 tol 은 `PointCache` 로, `Moved{base,motion}` 의
모션은 **면이 든다**. ★★ 그런데 그 목적지 `Vertex` 는 Q2 의 ①②를 **표현할 수 없다.**

### Q4. `SurfaceDef` 를 지우면 남는 것은

```rust
surface_motion: HashMap<Handle<Surface>, Handle<MotionNode>>   // 없으면 world
```

★★★★★ **함정 — 기본값의 극성이 뒤집힌다.** 오늘 기록 없는 surface 는 안전한 쪽으로 읽힌다:

```rust
model.surface_defs.get(&src).copied().unwrap_or(SurfaceDef::Inexact)   // transform.rs:294
// nacre-ops/src/planes.rs:102 도 같은 규약
```

지우면 그 기본값이 **«world 프레임의 정확한 평면»** 이 된다 — 정반대이고 **조용히 틀린다.**
⇒ 먼저 **기록 없는 surface 를 만들 수 없게** 해야 한다(`pub surfaces: Store<Surface>` 를 닫는 것).

### Q5. 원통이 오면 (M6) 이 구조가 버티나

★ 오늘 `Surface::Cylinder` 는 **생산자가 0** 이다(실측). 원통의 진실은 축+반지름이고 그것은
variant **자신 안에** 있다 ⇒ 불변식은 **variant 별**이다: *"모든 **평면**이 점을 갖는다"* 이지
*"모든 surface"* 가 아니다. 이 문장이 `Inexact` 삭제의 조건이다.

## 3. 어떤 답이든 만족해야 하는 제약

| | |
|---|---|
| C1 | **진실은 하나, 나머지는 캐시.** 같은 것을 두 가지로 말할 수 있으면 안 된다 |
| C2 | ★ **base case 는 «수» 다** — 종료가 거기서 보장된다. 기하가 기하만 가리키면 안 된다 |
| C3 | ★ **발견된 좌표는 `Rat` 에 안 들어간다** — 그런 점은 **가리켜야** 한다 |
| C4 | 모션이 섞인 판정은 정수 Shewchuk 을 못 쓴다 ⇒ **f64 필터 + 고정밀 상승**. (기존 규칙, 새 예외 아님 — `truth-and-cache.md` 「정확 경로의 조건」) |
| C5 | append-only ⇒ 참조는 **과거로만** 간다(DAG). 순환은 타입에만 있고 데이터에는 없다 |
| C6 | 깊이는 **사용자 조작당 1단**만 자란다(불리언이 평면을 안 만들므로) — 허용 가능 |
| C7 | ★ 거절은 **정직하게, 이름을 붙여서.** 조용히 틀리지 않는다 |
| C8 | `Rat` 을 넓히지 않는다. 중간값만 넓힌다 |

★★★★★ **C2 와 C3 이 긴장한다** — C3 은 «가리켜라» 이고 C2 는 «수에서 끝내라» 이다.
`VertexDef::At` 이 그 둘을 동시에 만족시키는 후보다(가리키되, 끝은 수).

## 4. 오늘까지 나온 후보 구조 (검토용, 확정 아님)

```rust
pub enum VertexDef {
    At([Rat; 3]),                      // base case — 사용자 치수 (좁다, 정확)
    ThreePlane([Handle<Surface>; 3]),  // 유도 (넓다, 필요할 때 실현)
}

pub struct Plane {
    points: [Handle<Vertex>; 3],
    motion: Option<Handle<MotionNode>>,
}
```

| 평면 | 세 점이 | |
|---|---|---|
| 구성 평면 (프로파일 벽·캡) | `At` 정점 셋 | 좁고 정확 — 오늘과 같은 값 |
| **datum 평면** (모서리 세 개) | `ThreePlane` 정점 셋 | 넓다 — 필요할 때 실현 |

**이 후보에 대해 아직 안 답한 것:**

- ★ 정점 저장이 평면당 3개씩 는다. 재사용률은? (구성 평면은 프로파일 코너를 공유할 것이다)
- ★ interning 키는 여전히 계수다. datum 평면은 이름을 못 만들 확률이 높다 ⇒ 0.39% 가 얼마나
  커지나? 크면 그것이 **`PlaneName` 확장의 첫 근거**다(오늘은 근거가 약해 미뤄 둠).
- ★ `At` 이 «어느 프레임의 좌표인가» 를 어떻게 말하나 — 정점에 모션을 달면 1.3 의 «모션은 면이
  든다» 와 충돌한다. (오늘은 `Origin::Moved{base, motion}` 이 그 역할을 한다)
- ★ `Origin` 을 없앨 때 `Discovered{tol}` 의 tol 은 `PointCache` 로 간다 — 그 캐시의 수명·무효화는?
- ★ f64 `Vertex.point` 를 언제 지우나(`3b`). 74곳이 읽는다.

## 5. 이 세션(2026-08-04~05)이 **틀렸던 것** — 같은 길로 다시 가지 말 것

| 내가 말한 것 | 실제 |
|---|---|
| *"`Origin::Constructed` 에 가드를 달자"* | ✗ 그 태그는 **정확성을 뜻하지 않는다**. 정확 경로로 만든 정점도 `Constructed` 이고 그 `point` 는 반올림이다 |
| *"불리언 능력을 포기하자"* | ✗ 설계 위반. 문서는 `Inexact` 를 **지우기로** 했다 |
| *"넓은 이름이 프레임을 연다"* | ✗ 이름 없는 404개의 법선은 **100% `i128`에 든다**. 막는 것은 `n·n` |
| *"`n·n` 이 필요하다"* | ✗ **파생물**이다. `n` 은 `rat_to_hp(n, prec)` 로 다시 realize 되지만(정의), `n·n` 은 `n` 의 함수다 |
| *"모션은 정점이 든다"* | ✗ **면이 든다** — 정점은 세 면의 교점이라 저절로 따라온다 |
| *"평면이 정점을 가리키면 무한 재귀"* | ✗ 불리언이 평면을 안 만들어 **안 자란다**. 깊이는 사용자 조작당 1단 |
| *"datum 평면은 M6+"* | ✗ **M5 다** — 곡면이 없다 |
| *"코퍼스 최대값이 상한"* (3회) | ✗ 타입에서 유도하라. 실측 최대는 **표본**이다 |

★★★★★ **그리고 방법론 하나**: 이 세션은 계획을 여섯 번 고쳐 썼고, 매번 **타입 구조가 안 정해져서**
같은 자리로 돌아왔다. ⇒ **타입을 먼저 확정하고 단계는 그 다음이다.**
